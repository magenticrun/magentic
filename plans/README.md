## Direction findings (options, not ranked against bugs)

Grounded in `docs/harness.md` phases and `docs/identity.md`; each would become a design/spike plan on request.

- **Authenticated edge** (DIR-01): every RPC resolves the caller from the gateway's own `USER` (`apps/gateway/src/Handlers.ts:26-33`); none of the four credential kinds in `docs/identity.md:30-33` exist. Gates policy, Slack, and Cursor. Effort L. Plan 002 is the interim control.
- **`policy.yaml`** (DIR-03): `packages/policy` is the `Decision` type and `layerAllowAll`; the enforcement plumbing (per-call guard, capability annotations) is complete and only the decision function is missing. Effort M–L; needs DIR-01 for a principal to match on. The doc explicitly rejects a code escape hatch in config; a webhook is the sanctioned extension.
- **Skills** (DIR-04): named on the README's first line, specified in `docs/harness.md:102-104`, zero code; the plugin contract has no skill domain, and the MCP plugin ignores server prompts, which would map onto skills. Effort M, additive, no auth dependency; the cheapest real differentiator.
- **`@magentic/store`** (DIR-02): audit is in-memory (`Audit.layerMemory` in `Server.ts`), so the compliance story dies with the process; tokens, approvals, memory, and cron all want the same SQLite file. Effort L.
- **MCP server route** (DIR-05): the gateway is now an MCP client; `docs/harness.md:268-271` specifies exposing agents as `ask_<agent>` MCP tools at `/mcp`. Effort M, but an unauthenticated `/mcp` is worse than none; sequence behind DIR-01 or bind loopback.
- **`magentic config check`** (DIR-06): the shell-plugin regression (plan 003) shows silent degradation when config and registrations disagree; a command that prints resolved agents → tools → plugins and exits non-zero on unmatched names is S–M and makes every later phase debuggable.

## Findings considered and rejected

- Delete the placeholder `packages/surface-slack` and `packages/surface-cursor`: they are scaffolding for documented phases 3 and 4, cost nothing at runtime; a one-line README in each would do.
- Split `apps/cli/src/tui/ChatView.tsx` (948 lines): real god-module, but L effort in an area with five of the last twelve commits; wait until TUI churn settles, then extract the run-event reducer first.
- `ContextEstimate` re-serialises history and tool schemas per model call: display-only, cost minor at current conversation sizes; revisit if `/context` becomes slow.
- `ConversationStore.list` re-reads every conversation: 32-way concurrent and superseded by the planned SQLite store.
- `ApiKeyProviders` rebuilds its model list per read: microseconds.
- MCP `roots` capability is deprecated in protocol 2026-07-28 (SEP-2577): twelve-month window, SDK still routes it; note only.
- `PluginHost.ts` uses `any` in four generic variance positions without `SAFETY:` comments: convention miss, no runtime risk.
- `ConfigAgents.ts` resolves `prompt.file` without containment: the config directory is operator-owned and already grants full prompt control.
- The phase-1 `Identity.layerLocal` / `Policy.layerAllowAll` / `Audit.layerMemory` wiring, in-process external plugins, RPC over REST, Effect AI over the Vercel SDK: documented decisions, not findings. Plan 002 addresses only where the code drifted from what `docs/identity.md` promised.
